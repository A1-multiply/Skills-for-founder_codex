# Reference Business Plan Writing Pattern

Use this reference when drafting or editing Korean startup support HWP business plans.
The reference comes from a completed Korean startup-package plan supplied by the user.
Do not copy its content, company name, item, numbers, or wording. Reuse only the writing
pattern, information hierarchy, layout rhythm, and visual organization.

## Overall Writing Pattern

- Start with a concise item definition, then immediately explain the customer pain and why the item solves it.
- Prefer short declarative Korean sentences ending in `~??, `~媛??, `~?덉젙`, `~?뺤씤`, `~異붿쭊`.
- Use a bracketed headline to summarize each cell or subsection:
  `[ ?듭떖 媛移?/ 臾몄젣 / ?ㅽ뻾 諛⑺뼢 / ?쒖옣 紐⑺몴 ]`
- Follow the headline with short bullets or compact paragraphs. Avoid loose essay-like writing.
- Use concrete anchors whenever possible:
  customer group, use case, measurable burden, cost/time reduction, current progress, channel, price, revenue logic, partner role.
- Where evidence is available, present it as a number or table rather than a vague claim.
- Never repeat the same growth-strategy structure for every item. Choose the structure that fits the item.

## Table Cell Layout Rules

- Default text: black, non-italic, normal weight.
- No blue text unless the user explicitly asks.
- No stretched letter spacing.
- Use compact line spacing.
- Give every filled cell a very small and consistent top padding before the first line.
- Keep the first line aligned consistently across filled cells.
- If the user asks for a line count, fit the text to that count:
  - 1-4 lines: normal compact cell.
  - 5-6 lines: reduce font height slightly.
  - 7-8 lines: reduce line spacing and wording.
  - 9-10 lines: tighter font/line spacing and shorter phrases.
  - More than 10 lines: split into another section or ask whether to shorten, unless the cell height allows it.
- If the bottom has too much empty space, balance visually with light top padding and compact spacing. Do not create huge blank bands between bullets.
- If text would overflow, shorten the text first; only then reduce size.

## Image And Visual Placement Pattern

The reference plan uses images and image placeholders as proof blocks, not decoration.

- In overview tables, reserve a separate image row/area after the summary text when the form allows it.
- Use two-column image placement where possible:
  - left: product/service summary, process, prototype, or screen
  - right: logo/icon, channel diagram, customer flow, or result example
- Put short captions under or inside the image area using angle brackets:
  `< ?꾩씠???붿빟 >`, `< ?쒕퉬???꾨줈?몄뒪 >`, `< 留ㅼ텧 怨꾪쉷 >`, `< ?ъ뾽 濡쒕뱶留?>`
- Images should support the written claim:
  prototype, process flow, service screen, market chart, roadmap, revenue table, test evidence.
- Avoid purely decorative images.

- `臾몄젣?몄떇`

  - Explain the trigger/problem.
  - Add market/customer evidence.
  - Use a small table when comparing features, costs, or user needs.

  - Then explain the difference in 2-3 short paragraphs.

## Editing Scope

This pattern applies to any HWP location, not only the 2026 preliminary startup-package overview table.
Before editing, inspect the document structure and choose the appropriate editing method:

- direct search/replace for existing prose
- insert/delete for body paragraphs
- table cell mapping for structured forms
- image placeholder/caption handling for visual sections
- custom map when the target coordinates are known

Do not hardcode one table coordinate or one business-plan form unless the user is working in that exact form.
